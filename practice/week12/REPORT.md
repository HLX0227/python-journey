# 我的 Git 历史分析报告

**数据集**：本人仓库 python-journey 的真实提交记录（2026-10-17 ~ 2026-11-04）
**规模**：31 次提交 · 1552 行新增 · 79 行删除
**工具**：Python 解析 + pandas 分析（`week12/analyze.py`）
**方法**：git log 导出 → 文本解析为 DataFrame → 分组统计 → 与 weekly-log.md 交叉对账

---

## 发现 1：我的产出是"爆发型"，不是"均匀型"

**证据**：代码量 Top3 天合计 902 行新增（10-27：484 / 10-19：224 / 10-17：194），
占全部新增的 **58%**；其余 16 个有提交的日子分摊剩下 42%。

**对账**：这三天在 weekly-log 中恰是"做了什么"栏最长的三篇
（10-27 = TODO 工具迁移 SQLite；10-19 = 字典+函数+持久化连轴转；10-17 = 环境日+列表日）。
数据与日记互相印证。

**所以呢**：整块时间（没课的下午/周末）是我的主产出窗口。
排学习计划时优先保护整块时段，零碎时间只做 25 分钟级的小任务（刷一题、改一个 bug）。

## 发现 2：周一是"频率冠军"，不是"体量冠军"

**证据**：按星期统计提交次数，Monday 10 次居首（Saturday 8 / Tuesday 6）；
但单日代码量冠军 484 行出现在周二。频率和体量是两个不同的冠军。

**所以呢**：周一适合安排"小步提交"类任务（修 bug、补笔记、改文档），
大功能和新概念留给能坐 3 小时的整块时段。别用"今天提交了几次"衡量产出，要看改了什么。

## 发现 3：我不是夜猫子型选手

**证据**：22 点及以后的提交仅 3 次 / 31 次（约 10%）；主力时段在傍晚至 21 点。

**所以呢**：不把新内容排在深夜。22 点之后只做收尾动作（提交、推送、填周报），
学习内容放在 19-21 点——数据支持这个时段的我更清醒。

## 附：方法自检（这份报告可信吗）

- 解析器对"只有 deletions 没有 insertions"的提交做了缺省处理（`or 0`），不会漏行
- 缺统计行的提交记为 0，报告中的 0 均为"真 0 或缺失"，未做区分（已知局限）
- Top3 结论与 weekly-log 独立对账通过
- 样本仅 19 天 31 次提交，结论适用于"当前学期节奏"，不代表长期习惯
